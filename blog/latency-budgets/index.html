Latency Budgets Are Design Documents

Published 2026-06-02 · 3 min read

A latency target becomes useful when it stops being one number and starts describing where time may be spent. A 200 ms request budget might look like this:

StageBudgetNotes
Network edge35 msGeographic variance
Application55 msValidation and orchestration
Database80 msQueries and retry allowance
Reserve30 msQueueing and unexpected work

The table is not a prediction. It is a compact agreement about priorities.

Measure boundaries

Instrumentation should follow the boundaries in the budget. A trace with only a total duration says a request was slow; spans around each stage say where an assumption failed.

const total = (budget) =>
  Object.values(budget)
    .reduce((sum, ms) => sum + ms, 0);

A useful performance target assigns ownership. An unowned target is only a wish.

Keep the reserve visible

Systems accumulate small costs. Explicit reserve prevents every component from assuming that all remaining time belongs to it.
